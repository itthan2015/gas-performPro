# ประวัติการพัฒนา (สรุปจากบทสนทนากับ Claude)

ลำดับคำขอของผู้ใช้และสิ่งที่ทำ — ใช้เป็นบริบทเมื่อพัฒนาต่อ

1. ต้นแบบ PerformPro (Design Component) → v2 โทนสีตาม Plant Access, หน้า login พนักงานตอบคำถามจากข้อมูลตัวเอง → v3 หน่วยงานเลือกได้หลายหน่วย, ผลฉบับก่อนหน้า, แนบไฟล์รายบุคคล, จัดการพนักงานและบทบาท
2. สร้าง Web App จริง: Apps Script + Supabase, ตาราง `PFormPro_*`, หน้าตาตามต้นแบบ
3. แก้ค้างที่ "กำลังโหลด…": แยก ScoringClient, watchdog, แสดงขั้นโหลด → สาเหตุจริงคือ HtmlService แปลง JS → โหลดแบบ base64 (v3.3)
4. นำเข้าผลรอบ 1/2569 จาก Excel เป็นข้อมูลรอบก่อนหน้า
5. เพิ่ม isactive (#ลาออก ใน remark) + หน้าโปรไฟล์พนักงาน · ตัวกรอง ปกติ/ลาออก ทุกหน้า
6. รายงานสรุปผลแสดงรายชื่อตาม filter · บัญชี admin ทุกเมนู
7. สถิติมาทำงาน (มาสาย ลาป่วย ลากิจ ขาดงาน ใบเตือน) สิทธิ์ admin/HR Admin/หัวหน้าแผนก-ฝ่าย HR + นำเข้า CSV
8. จัดการรอบการประเมิน (HR Admin, admin)
9. วันที่ทุกหน้าเป็น dd/MM/yyyy
10. แก้ขอบเขตผู้ประเมินไม่อัปเดตหลัง login · dialog "ระบบกำลังทำงาน" ทุกการเปลี่ยนหน้าและหน้า login
11. ตัวเลือกหน่วยงานแสดงเป็นกลุ่ม ฝ่าย › แผนก แบบช่องติ๊ก · คลิกแผนกในจัดการพนักงานแสดงรายชื่อ
12. ปรับสถานะพนักงานจากไฟล์สถานะ (ลาออก = ไม่รับประเมิน) · แก้ SQL temp table → VALUES
13. Recode แบบฟอร์มตามไฟล์ล่าสุด rev.10.11.69 (9 แบบฟอร์ม) · แก้ `c.active` → `is_active`
14. หน้าแบบฟอร์มเป็นการ์ดหัวเรื่อง คลิกดูรายละเอียด
15. Template นำเข้าพนักงาน + นำเข้าจาก JSON ล่าสุด · ตรวจลาออกจาก remark/แผนก · PersonalActive.json (ไม่อยู่ในไฟล์ = ลาออก)
16. ผลประเมินฉบับก่อนหน้าแสดงตามหัวข้อแบบฟอร์มเดิม
17. ตั้งค่าเปิด/ปิดให้พนักงานดูผล
18. Timeline สายอนุมัติ + เมนู Help? คู่มือพร้อมตัวอย่างการคำนวณ · แก้คะแนนเกินเต็ม (ร่างจากแบบฟอร์มเดิม)
19. เมนูซ้ายหุบได้ (hamburger)
20. สายอนุมัติใหม่: ไม่ใช่หัวหน้าฝ่าย/เกรด <5 ต้องผ่านหัวหน้าฝ่าย
21. แก้เมนูพนักงานไม่เปิด (สถานะแบบประเมินว่าง) + `91_fix_eval_status.sql`
22. จัดทำ repo นี้ (2026-11-12)

## ปัญหาที่เคยเจอและวิธีแก้ (อย่าทำซ้ำ)
- HtmlService include JS ยาวที่มี HTML ในสตริง → ค้าง → ใช้ base64 loader
- Supabase SQL Editor ไม่เก็บ temp table ข้าม statement → ใช้ VALUES
- คอลัมน์รอบคือ `is_active`
- `// comment` ในบรรทัดเดียวกับ `return` ใน template → syntax error
- สถานะที่ไม่รู้จักทำให้ `ST[st][1]` พัง → fallback เป็น none
