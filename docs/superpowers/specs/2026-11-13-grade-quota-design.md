# เกณฑ์เกรด 4 ระดับ + โควต้าตามกลุ่มผู้ประเมิน — Design

วันที่ 2026-11-13 · สถานะ: รออนุมัติ

## เจตนา
- พนักงานเกรด 1–3 เปลี่ยนจากเกรด 7 ระดับ (A+ … F) เป็น 4 ระดับ: **A ≥ 85 · B 75–84.99 · C 70–74.99 · D < 70**
- จำกัดสัดส่วนเกรดในแต่ละกลุ่มของผู้ประเมิน: **A ≤ 20% · B ≤ 50% · C ≤ 30% · D ไม่จำกัด** เพื่อคุมการให้เกรดสูงเกินจริง
- HR/admin ปรับเกณฑ์และโควต้าเองได้จากหน้าจัดการ
- เกรด 4–5 (แบบฟอร์ม g45, สเกล 5…1 `GR_SUP`) **คงเดิม** ไม่มีโควต้า

## กติกา (ผู้ใช้ตัดสินแล้ว)
1. **เกินโควต้า → ห้ามส่ง** ผู้ประเมินต้องกลับไปปรับคะแนนเอง (ไม่ลดเกรดอัตโนมัติ)
2. **ปัดเศษโควต้า**: เศษ ≥ .5 ปัดขึ้น, < .5 ปัดลง (เช่น 3 คน → A 1 · B 2 · C 1 · กลุ่ม 1–2 คน → A 0)
   - เศษ = .5 พอดีปัดขึ้น *(การตัดสินของผู้สร้าง: ผู้ใช้กำหนด "เกิน .5 ขึ้น / น้อยกว่าลง")*
3. **โควต้าแยกกันเด็ดขาด**: ที่ใช้ไม่หมดไม่ยกให้เกรดถัดไป
4. **เก็บค่าแยกตามรอบการประเมิน** (แนวทาง A)

## แนวทางที่พิจารณา
| แนวทาง | สรุป | ผล |
| --- | --- | --- |
| **A. คอลัมน์ `grade_cfg` ในรอบการประเมิน** | เกณฑ์ผูกกับรอบ รอบเก่าคงสเกลเดิม | **เลือก** — ประวัติไม่เพี้ยน เปลี่ยนเกณฑ์ปีหน้าได้ ต้องรัน migration 1 ไฟล์ |
| B. Script Properties JSON | ไม่แตะฐานข้อมูล | ไม่เลือก — แก้ค่าแล้วประวัติรอบเก่าคิดเกรดผิด ไม่มี audit |
| C. ฝังสเกลใหม่ในโค้ด แก้ได้แค่ % | เร็วสุด | ไม่เลือก — ผู้ใช้ต้องการแก้จุดตัดได้จากหน้าจัดการ |

## การออกแบบ

### ข้อมูล
- migration `sql/92_grade_cfg.sql` (รันซ้ำได้): `alter table "PFormPro_eval_cycles" add column if not exists grade_cfg jsonb;`
  แล้วตั้งค่าเริ่มต้นให้ **รอบที่เปิดใช้อยู่** (เฉพาะที่ยัง null) · แก้ `00_schema.sql` ให้มีคอลัมน์นี้
- รูปแบบ `grade_cfg`:
  ```json
  { "levels": [ {"g":"A","min":85,"label":"ดีเยี่ยม"}, {"g":"B","min":75,"label":"ดี"},
                {"g":"C","min":70,"label":"พอใช้"},   {"g":"D","min":0,"label":"ต้องปรับปรุง"} ],
    "quota":  { "A":20, "B":50, "C":30 } }
  ```
  ชื่อระดับ (label) เป็นค่าเริ่มต้นของผู้สร้าง แก้ได้ในหน้าจัดการ
- `grade_cfg = null` → ใช้สเกล 7 ระดับเดิม (`GR_NEW`) และไม่มีโควต้า (รอบเก่า/ข้อมูลนำเข้า)
- สร้างรอบใหม่ (`apiCycleSave` แบบเพิ่ม) → คัดลอก `grade_cfg` จากรอบล่าสุดที่มีค่า ถ้าไม่มีใช้ค่าเริ่มต้นด้านบน

### การคิดเกรด (Scoring.gs = ScoringClient.html ต้องตรงกัน)
- `calcScore(form, att, sc, W, cfg)` เพิ่มพารามิเตอร์ `cfg` (grade_cfg ของรอบ)
  - ฟอร์ม 4–5 → `GR_SUP` เหมือนเดิม
  - ฟอร์ม 1–3 + มี cfg → เลือกระดับแรกที่ `total >= min` (เรียง min มาก→น้อย) · ไม่มี cfg → สเกลเดิม
- เพิ่ม `gradeLevels(form, cfg)` คืนรายการระดับในรูปแบบเดียวกับ `GR_NEW` (`[g, label, ช่วง, คำอธิบาย]`) ให้แดชบอร์ด/Help/ประวัติใช้
- แสดงเกรดที่บันทึกไว้: หาในสเกลของรอบนั้นก่อน ไม่เจอค่อยหาใน `GR_NEW` เดิม (กันข้อมูลนำเข้าเกรดเก่าในรอบที่มี cfg แสดงไม่ได้)
- ทุกจุดที่เรียก `calcScore` ส่ง cfg ของรอบที่เกี่ยวข้อง: `save_`, `apiSubmit`, คำนวณใหม่หลังบันทึก/นำเข้าสถิติ (Code.gs ~481, ~533), `previous_` (อ่าน `grade_cfg` ของรอบนั้น), หน้าเว็บใช้ `S.boot.cycle.grade_cfg`

### โควต้า
- **กลุ่ม** = พนักงานในขอบเขตสิทธิ์ (`inScope_`) ของ **ผู้ที่กดส่ง** ที่ active, `evaluate` ไม่เป็น false, แบบฟอร์มเกรด 1–3 (`e.form === 'new'`) และไม่ใช่ตัวผู้ส่งเอง
  *(การตัดสินของผู้สร้าง — ระบบไม่ได้บันทึกผู้ประเมินรายคน; admin/ผู้มีขอบเขตทั้งบริษัท = ทั้งบริษัทเป็นกลุ่มเดียว)*
- **ฐาน n** = จำนวนคนในกลุ่ม · **เพดาน** ของเกรด X = `floor(n × X% / 100 + 0.5)`
- **ที่ใช้ไป** = แบบประเมินรอบปัจจุบันของคนในกลุ่มที่สถานะ ไม่ใช่ none/draft/returned นับตามเกรดที่บันทึกไว้
- `apiSubmit` (เฉพาะฟอร์ม 1–3 และรอบมี cfg): ถ้า ที่ใช้ไป(เกรดนี้, ไม่นับคนนี้) + 1 > เพดาน → throw
  `"เกรด A เกินโควต้าของกลุ่ม (ใช้แล้ว 2 จาก 2 คน · กลุ่ม 10 คน) กรุณาปรับคะแนนก่อนส่ง"`
  ห่อ check + save ด้วย `LockService.getScriptLock()` กันส่งพร้อมกันแล้วหลุดโควต้า
- อนุมัติ/ส่งกลับ/HR บันทึก ไม่ตรวจโควต้า · ส่งกลับ (returned) แล้วโควต้าคืนอัตโนมัติ
- คะแนนถูกคำนวณใหม่ภายหลัง (นำเข้าสถิติ, แก้เกณฑ์) จนเกิน → **ไม่บล็อกย้อนหลัง** แสดงคำเตือนแดงในหน้ารายชื่อ

### หน้าเว็บ
- **หน้าใหม่ "เกณฑ์เกรดและโควต้า"** (`grades`, เมนูของ hr/admin)
  - เลือกรอบ (ค่าเริ่มต้น = รอบที่เปิดอยู่) · ตาราง 4 แถว: เกรด, คะแนนขั้นต่ำ, ชื่อระดับ, % โควต้า (D แสดง "ไม่จำกัด")
  - ตรวจ: min A > B > C > 0, % เป็น 0–100 · แสดงตัวอย่างโควต้าของกลุ่ม 1/3/5/10 คน
  - ปุ่ม "ใช้สเกลเดิม 7 ระดับ" = ตั้ง cfg เป็น null (ไม่มีโควต้า)
  - บันทึก → `apiGradeCfgSave(token, cycleId, cfg)` (requireRole hr) → คำนวณ total/grade ใหม่ของแบบประเมินที่ยังไม่ done ในรอบนั้น
  - `apiGradeCfgGet(token, cycleId)` คืน cfg + รายชื่อรอบ
- **หน้ารายชื่อพนักงาน**: ผู้ที่ส่งแบบประเมินได้ (eval/div/admin) เห็นแถบ `โควต้ากลุ่ม (10 คน): A 1/2 · B 3/5 · C 0/3 · D 1` เกินเป็นสีแดง (`apiListEmployees` คืน `quota`)
- **แดชบอร์ด** การกระจายเกรดระดับ 1–3 และ **Help** ตารางเกณฑ์ ใช้สเกลของรอบปัจจุบัน + อธิบายโควต้า

## เป้าหมาย / ไม่ใช่เป้าหมาย
- ไม่แปลงเกรดของผลประเมินรอบเก่า · ไม่เปลี่ยนเกรด 4–5 · ไม่ยกโควต้าข้ามเกรด · ไม่ลดเกรดอัตโนมัติ
- ไม่เพิ่ม/ลดจำนวนระดับในหน้าจัดการ (คงที่ 4 ระดับ A–D) *(การตัดสินของผู้สร้าง)*
- **Anti-goal**: เกณฑ์ใหม่ทำให้ประวัติรอบเก่าแสดงเกรด/ความหมายผิด
