# PerformPro · Google Apps Script + Supabase

หน้าตา โทนสี และโครงสร้างหน้าจอตามต้นแบบ PerformPro v3

## ตารางในฐานข้อมูล (ขึ้นต้นด้วย `PFormPro_` ทั้งหมด)
| ตาราง | เก็บอะไร |
| --- | --- |
| `PFormPro_divisions` | ฝ่าย |
| `PFormPro_departments` | แผนก (ผูกกับฝ่าย) |
| `PFormPro_employees` | พนักงาน + ข้อมูลยืนยันตัวตน |
| `PFormPro_app_users` | บัญชีหัวหน้า/ผู้อนุมัติ/ผู้บริหาร/HR บทบาท และหน่วยงานที่ดูแล (หลายหน่วยงาน) |
| `PFormPro_login_attempts` | จำนวนครั้งที่เข้าสู่ระบบผิด / การล็อก |
| `PFormPro_eval_cycles` | รอบการประเมิน (เปิดใช้ได้ทีละ 1 รอบ) |
| `PFormPro_attendance` | สถิติมาทำงานต่อรอบ |
| `PFormPro_weight_sets` | น้ำหนักคะแนนแต่ละแบบฟอร์ม |

| `PFormPro_attachments` | ข้อมูลไฟล์แนบ (ตัวไฟล์อยู่ใน Storage bucket `pformpro-attachments`) |

> ชื่อตารางมีตัวพิมพ์ใหญ่ เวลาเขียน SQL เองต้องใส่เครื่องหมายคำพูด เช่น `select * from "PFormPro_employees";`

โทนสีหน้าเว็บอิงตาม Plant Access (indigo/violet การ์ดขาวมุมโค้ง KPI ไล่สี)

ระบบประเมินผลการปฏิบัติงานประจำปี ทำงานเป็น Web App บน Google Apps Script และเก็บข้อมูลใน Supabase (PostgreSQL)

## ขั้นตอนติดตั้ง

### 1. Supabase
1. สร้างโปรเจกต์ที่ https://supabase.com
2. เปิด **SQL Editor** → วางเนื้อหา `schema.sql` → **Run**
3. แก้อีเมลในตาราง `PFormPro_app_users` ให้เป็นบัญชี Google จริงของผู้ใช้ (อย่างน้อยบัญชี HR ของคุณเอง)
4. ไปที่ **Project Settings → API** คัดลอก
   - `Project URL` (เช่น `https://abcd.supabase.co`)
   - `service_role` key (เก็บเป็นความลับ ห้ามใส่ในหน้าเว็บ)

### 2. Google Apps Script
1. เปิด https://script.google.com → **New project** ตั้งชื่อ `PerformPro`
2. สร้างไฟล์ให้ชื่อตรงกัน: `Code.gs`, `Scoring.gs` (Script) และ `Index`, `Styles`, `App`, `ScoringClient` (HTML) แล้ววางเนื้อหาแต่ละไฟล์
3. **Project Settings → Script Properties** เพิ่ม
   - `SUPABASE_URL` = Project URL
   - `SUPABASE_SERVICE_KEY` = service_role key
4. ใน Editor เลือกฟังก์ชัน `setupDemoPasswords` แล้วกด **Run** หนึ่งครั้ง ระบบจะตั้งรหัสผ่านเริ่มต้น `pp123456` ให้ทุกบัญชีใน `PFormPro_app_users` ที่ยังไม่มีรหัสผ่าน
5. **Deploy → New deployment → Web app**
   - *Execute as* = **Me**
   - *Who has access* = **Anyone** (ระบบใช้หน้าเข้าสู่ระบบของตัวเอง ไม่ต้องใช้บัญชี Google)
6. เปิด URL ของ Web app แล้วเข้าสู่ระบบด้วยบัญชี HR (`31007` / `pp123456`) จากนั้นเปลี่ยนรหัสผ่านทุกบัญชีที่เมนู **จัดการพนักงาน**

## การเข้าสู่ระบบ

| ผู้ใช้ | วิธีเข้าสู่ระบบ |
| --- | --- |
| พนักงาน | กรอกรหัสพนักงาน → ระบบ **สุ่มถาม 1 ข้อ** จาก 4 ตัวท้ายเลขบัตรประชาชน, วันเดือนปีเกิด (พ.ศ.) หรือ 4 ตัวท้ายเบอร์โทรศัพท์ |
| หัวหน้า / ผู้อนุมัติ / ผู้บริหาร / HR | รหัสพนักงาน + รหัสผ่าน (บัญชีในตาราง `PFormPro_app_users`) |

- ตอบผิดหรือใส่รหัสผ่านผิดได้ **3 ครั้ง** ครั้งที่ 3 บัญชีจะถูกล็อก HR ปลดล็อกได้ที่เมนู **จัดการพนักงาน**
- คำถามที่สุ่มได้มีอายุ 5 นาที
- session มีอายุ 6 ชั่วโมง เก็บที่ฝั่งเซิร์ฟเวอร์ (CacheService) หน้าเว็บถือเพียง token
- รหัสผ่านเก็บเป็น SHA-256 + salt ไม่เก็บรหัสผ่านจริง
- ข้อมูลยืนยันตัวตนอยู่ในตาราง `PFormPro_employees` คอลัมน์ `national_id_last4`, `birth_date`, `phone_last4` ค่าใน `schema.sql` เป็นค่าตัวอย่าง ต้องแทนด้วยข้อมูลจริงจากระบบบุคคล

## การจัดการสิทธิ์ (แต่ละฝ่ายไม่เห็นข้อมูลฝ่ายอื่น)

ทุกคำขอถูกกรองที่ **เซิร์ฟเวอร์** ตามบทบาทและขอบเขต ข้อมูลนอกขอบเขตจึงไม่ถูกส่งมาหน้าเว็บเลย

| บทบาท | ขอบเขต | ทำอะไรได้ |
| --- | --- | --- |
| `eval` ผู้ประเมิน | `dept` แผนก | ประเมินพนักงานระดับ 1–3 ในแผนก |
| `div` ผู้อนุมัติระดับฝ่าย | `div` ฝ่าย | ประเมินหัวหน้า (ระดับ 4–5) และอนุมัติระดับฝ่าย |
| `exec` ผู้บริหาร | `all` | อนุมัติระดับบริหาร ดูแดชบอร์ดทั้งบริษัท |
| `hr` ฝ่ายบุคคล | `all` | บันทึกคะแนน ตั้งค่าน้ำหนัก จัดการบัญชีและปลดล็อก |
| พนักงาน | ตนเอง | ดูผลของตนหลังอนุมัติระดับบริหาร และกดรับทราบ |

## จัดการพนักงาน (เมนูของฝ่ายบุคคล)
- **แท็บพนักงาน:** เพิ่ม/แก้ไขข้อมูลพนักงาน ระดับ แผนก วันที่เริ่มงาน ข้อมูลยืนยันตัวตน ปิดใช้งาน หรือไม่นำเข้ารอบประเมิน
- **บทบาทพนักงาน:** พนักงาน / ผู้ประเมิน / ผู้อนุมัติระดับฝ่าย / ผู้บริหาร / ฝ่ายบุคคล บทบาทอื่นที่ไม่ใช่พนักงานต้องตั้งรหัสผ่าน
- **หน่วยงานที่ดูแลเลือกได้หลายหน่วยงาน:** เลือกขอบเขตเป็นแผนก ฝ่าย หรือทั้งบริษัท แล้วติ๊กได้หลายแผนก/หลายฝ่าย (เก็บในคอลัมน์ `PFormPro_app_users.scope_values` แบบ array)
- **แท็บหน่วยงาน:** เพิ่ม/ลบฝ่ายและแผนก (ลบได้เมื่อไม่มีพนักงานหรือแผนกอยู่ข้างใน)
- ปลดล็อกบัญชีที่ตอบผิดเกิน 3 ครั้งได้ในแผงแก้ไขพนักงาน

## ผลประเมินฉบับก่อนหน้า
หน้าประเมิน หน้าผลของฉัน และรายงาน แสดงผลประเมินรอบก่อนหน้าที่ `status = 'done'` ของพนักงานคนนั้น พร้อมแนวโน้มคะแนนเทียบรอบก่อน กดแต่ละรอบเพื่อดูคะแนนราย Part
`schema.sql` ใส่ผลย้อนหลังตัวอย่าง 2 รอบ (เฉพาะคะแนนรวมและเกรด) ให้นำเข้าข้อมูลจริงจากระบบเดิมลงตาราง `PFormPro_evaluations` โดยใช้ `cycle_id` ของรอบนั้น

## เอกสารแนบ
- แนบเอกสาร PDF / Word / Excel / รูปภาพ ได้ทีละหลายไฟล์ ไม่เกิน 10 MB ต่อไฟล์
- ไฟล์เก็บใน Supabase Storage bucket `pformpro-attachments` (private) ข้อมูลไฟล์อยู่ในตาราง `PFormPro_attachments` เปิดดูผ่าน signed URL อายุ 1 ชั่วโมง
- ผู้อัปโหลดได้: พนักงาน (ของตนเอง), ผู้ประเมิน / ผู้อนุมัติระดับฝ่าย / HR (เฉพาะพนักงานในขอบเขต) ลบได้เฉพาะผู้อัปโหลดหรือ HR
- `schema.sql` สร้าง bucket ให้แล้ว ถ้า SQL Editor แจ้งว่าไม่มีสิทธิ์กับ `storage.buckets` ให้สร้าง bucket ชื่อ `pformpro-attachments` (ไม่เปิด public) ที่เมนู Storage เอง

## สายการอนุมัติ
ผู้ประเมินส่ง → อนุมัติระดับฝ่าย → อนุมัติระดับบริหาร → พนักงานรับทราบ → ฝ่ายบุคคลบันทึกคะแนน
(แบบฟอร์มระดับ 4–5 ที่ผู้อนุมัติระดับฝ่ายเป็นผู้ประเมินจะข้ามขั้นอนุมัติระดับฝ่าย) ผู้อนุมัติระดับฝ่าย/บริหารส่งกลับแก้ไขพร้อมเหตุผลได้

## นำเข้าข้อมูลพนักงานและสถิติมาทำงานจาก Excel
1. ส่งออกชีต `Data` เป็น CSV ให้คอลัมน์ตรงกับตาราง `PFormPro_employees` (`emp_code, full_name, grade, position, department_id, start_date, national_id_last4, birth_date, phone_last4`)
2. ส่งออกสถิติเป็น CSV ให้ตรงกับตาราง `PFormPro_attendance` (`cycle_id, emp_code, late_min, sick_days, personal_days, absent_days`)
3. Supabase → **Table Editor** → เลือกตาราง → **Insert → Import data from CSV**

update eval_cycles set is_active = false;

## นำเข้าผลประเมินรอบที่ 1/2569 (ข้อมูลรอบก่อนหน้า)
1. รัน `schema.sql` ก่อน (รอบที่เปิดใช้งานคือ **ประจำปี 2569 ครั้งที่ 2**)
2. รัน `import_2569_round1.sql` ใน SQL Editor ไฟล์นี้จะ
   - สร้างรอบ "ประจำปี 2569 ครั้งที่ 1" (ปิดแล้ว)
   - เพิ่ม/อัปเดตพนักงานระดับ 1–5 ทั้งหมด 296 คน พร้อมฝ่าย/แผนกตามไฟล์ Excel
   - นำเข้าผลประเมิน 245 คน พร้อมคะแนนราย Part ตามแบบฟอร์มของแต่ละระดับ

## นำเข้าข้อมูลโปรไฟล์พนักงาน (isactive)
1. รัน `import_employee_profile.sql` หลัง `import_2569_round1.sql`

   - อัปเดตเลขบัตร 4 ตัวท้าย วันเกิด เบอร์โทร หมายเหตุ ของพนักงาน 295 คน

## บัญชีผู้ดูแลระบบ (admin)
- รหัส `admin` · รหัสผ่าน `(ตั้งเองตอนติดตั้ง — ดู sql/30_admin_account.sql)` · เข้าทางแท็บ "หัวหน้า / HR"
- เข้าได้ทุกเมนู: แดชบอร์ด รายการรออนุมัติ พนักงาน รายงาน ตั้งค่าน้ำหนักคะแนน จัดการพนักงาน
- เห็นพนักงานทั้งบริษัท แก้ไขแบบประเมิน อนุมัติ/ส่งกลับได้ทุกขั้น อัปโหลด/ลบเอกสารได้ทุกคน
- สร้างบัญชี: รัน `admin_account.sql` ใน SQL Editor หรือรันฟังก์ชัน `setupAdmin` ใน Apps Script (เลือกอย่างใดอย่างหนึ่ง)
- เปลี่ยนรหัสผ่านได้ที่ จัดการพนักงาน → ผู้ดูแลระบบ → แก้ไขข้อมูล

## รอบการประเมิน
- เมนู **รอบการประเมิน** (เฉพาะ HR Admin และ Admin): เพิ่ม/แก้ไขรอบ (ปี พ.ศ. ครั้งที่ ช่วงวันที่ของข้อมูล) เปิดใช้เป็นรอบปัจจุบัน และลบรอบ
- เปิดใช้ได้ทีละ 1 รอบ เปลี่ยนรอบแล้วข้อมูลรอบเดิมยังอยู่ครบ ดูย้อนหลังได้ที่รายงานสรุปผล
- ลบได้เฉพาะรอบที่ปิดอยู่และยังไม่มีแบบประเมิน

## สถิติมาทำงาน
- รัน `attendance_discipline.sql` ก่อนใช้งาน (เพิ่มคอลัมน์หนังสือเตือน)
- เมนู **สถิติมาทำงาน** แสดงเฉพาะ Admin, HR Admin, หัวหน้าแผนก HR (บทบาทผู้ประเมิน) และหัวหน้าฝ่าย HR (บทบาทผู้อนุมัติระดับฝ่าย)
- หน่วยงาน HR: ตั้ง Script Property `HR_UNITS` เป็นชื่อแผนก/ฝ่าย คั่นด้วย , ถ้าไม่ตั้ง ระบบถือว่าหน่วยงานที่ชื่อมีคำว่า "บุคคล" หรือ "HR" คือ HR
- บันทึกแล้วระบบคำนวณ Part การรักษาระเบียบวินัย คะแนนรวม และเกรด ของแบบประเมินที่ยังไม่ปิดใหม่ทันที
- ในแบบประเมิน ผู้ประเมินแก้ตัวเลขสถิติไม่ได้ (อ่านอย่างเดียว)
- **นำเข้าไฟล์:** กด "ดาวน์โหลดไฟล์ตัวอย่าง" ได้ CSV รายชื่อพนักงานทั้งหมดพร้อมค่าปัจจุบัน แก้ใน Excel แล้ว Save As → CSV UTF-8 กด "นำเข้า CSV" ระบบจะไฮไลต์ช่องที่เปลี่ยน ตรวจแล้วกดบันทึก

## นำเข้าข้อมูลพนักงาน
- ไฟล์ template: `employee_import_template.csv` (มีตัวอย่าง 2 แถว) · คำอธิบายคอลัมน์: `employee_import_columns.csv`
- หรือกด "ดาวน์โหลด template" ในหน้าจัดการพนักงาน จะได้ไฟล์พร้อมรายชื่อพนักงานปัจจุบันให้แก้ไขต่อ
- แก้ใน Excel แล้ว Save As → **CSV UTF-8** → กด "นำเข้าพนักงาน (CSV)" ระบบตรวจไฟล์และแสดงผลก่อนยืนยัน
- รหัสที่มีอยู่แล้ว = อัปเดตเฉพาะช่องที่กรอก (ช่องว่าง = คงค่าเดิม) · รหัสใหม่ = เพิ่มพนักงาน (ต้องมีชื่อ เกรด แผนก)
- ไม่เปลี่ยนบทบาท/รหัสผ่าน (ตั้งที่หน้าจัดการพนักงานรายคน)
